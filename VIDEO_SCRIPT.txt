[2:00 – 3:00] Data Generation & Ingestion
"In Stage 1, synthetic data is generated using Faker: 1000 users, 500 products, 50,000 clickstream events, 10,000 transactions, and about 20,000 ratings. We intentionally added missing values, duplicates, and invalid ratings to test validation.
Stage 2 ingests data from two sources — local CSV files and product data from the FakeStore REST API. This showed us how heterogeneous ingestion works with retry logic."
Action: Show data/raw/ folder, open one CSV, and display logs/ingestion.log.
Reflection: "This stage taught us how important it is to simulate real‑world messy data. It was tricky at first, but it made validation meaningful."
 
[3:00 – 4:00] Validation & Quality Report
"Stage 3 validates datasets for schema mismatches, missing values, duplicates, and range violations (like ratings between 1 and 5)."

[4:00 – 5:00] Preparation & EDA
"Stage 4 prepares the data: imputes missing ages, encodes categorical variables, normalizes prices, and removes invalid ratings.
Exploratory analysis included user age distribution, product categories, rating distribution, and a user‑item heatmap. The interaction matrix showed ~96% sparsity, which is typical for recommendation systems."
Action: Run cells in notebooks/eda_analysis.ipynb.
Reflection: "This stage helped us appreciate how sparse recommendation data can be. Visualizing it made the challenge very clear."
 
[5:00 – 6:00] Feature Engineering
"Stage 5 builds three feature tables:
User features (activity, average rating, spend)
Item features (popularity, conversion rates)
User‑item features (interaction flags and counts)
We also created a SQL schema for the feature warehouse."
Action: Show data/features/user_features.csv and data/features/schema.sql.
Reflection: "Designing features was one of the most creative parts. We debated which features would actually help the models, and it felt like solving a puzzle."
 
[6:00 – 7:00] Feature Store & Versioning
"Stage 6 registers features in a custom SQLite feature store, which tracks names, versions, data types, sources, and transformations. Each snapshot is timestamped.
Stage 7 versions datasets using SHA‑256 hashes, skipping unchanged files."
Action: Display data/feature_store/registry.db, data/versions/manifest.json, and screenshot 11_data_versioning.png.
Reflection: "We realized versioning is essential for reproducibility. At first, we underestimated it, but later we saw how it prevents confusion when datasets evolve."
 
[7:00 – 8:30] Model Training & Evaluation
"Stage 8 trains two models:
SVD collaborative filtering with 50 latent factors, RMSE ≈ 1.47
Content‑based filtering using cosine similarity on item features
Both are evaluated with Precision@K, Recall@K, and NDCG@K for K=5,10,20. Interestingly, the content‑based model performed better on ranking metrics because it uses actual feature similarity instead of sparse ratings."
Action: Show screenshot 09_model_performance.png. "All experiments are tracked in MLflow with parameters, metrics, and artifacts logged."
Action: Show MLflow screenshot 13_mlflow_tracking.png and models/ folder with .pkl files.
Reflection: "This stage was challenging. We had to interpret metrics carefully, and it taught us that lower RMSE doesn’t always mean better recommendations."
